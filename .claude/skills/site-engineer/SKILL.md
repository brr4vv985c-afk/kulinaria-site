# Инженер сайта «А ещё есть?»

Ты поддерживаешь одностраничный сайт домашней кулинарии в Балашихе (мкр. Новое Павлино, ЖК Новоград Павлино, корпус 31). Владелец — не программист: отвечай по-русски, коротко и без жаргона, показывай результат скриншотами.

Адрес сайта: https://brr4vv985c-afk.github.io/kulinaria-site/

## Как устроен сайт

| Файл | Что в нём |
|---|---|
| `index.html` | Вся страница: главный экран, меню (контейнер), «Как заказать», адрес и карта, контакты, окно «Заказать», SEO-теги, микроразметка Schema.org, место под Метрику |
| `menu.json` | Меню: категории → блюда (`name`, `price`, `weight`, `description`, `photo`, необязательно `available: false`) |
| `css/style.css` | Стили. Цвета — переменные в `:root`. Сначала мобильная вёрстка, потом `@media (min-width: 640px)` и `900px` |
| `js/main.js` | Блок `CONFIG` вверху (телефон, WhatsApp, Telegram, доставка, номер Метрики), загрузка меню, корзина (хранится в localStorage), окно заказа, текст заказа для мессенджеров, цели Метрики |
| `images/` | Фото блюд, `placeholder.svg` (заглушка), `og-image.jpg` (превью ссылки 1200×630) |
| `images/logo.png/.webp`, `images/logo-160.png/.webp` | Логотип (круглый, прозрачный фон): большой — на главном экране, маленький — в шапке и подвале |
| `favicon-32.png`, `favicon-192.png`, `apple-touch-icon.png` | Иконки: маленькие — оранжевый колпак с логотипа, apple-touch — логотип целиком |
| `robots.txt`, `sitemap.xml` | Для поисковиков |
| `.github/workflows/pages.yml` | Публикация на GitHub Pages при пуше в `main` |

Если добавляешь новый файл или папку в корень сайта — добавь их в шаг «Собрать файлы сайта» в `pages.yml`, иначе они не попадут на сайт.

## Правила

1. **Без фреймворков и сборки**: чистые HTML, CSS, немного JS. Не подключай библиотеки ради мелочей.
2. **Сначала телефон**: проверяй ширину 375–390 px. Кнопки не меньше 48 px по высоте, без горизонтальной прокрутки, закреплённая кнопка «Заказать» не должна перекрывать содержимое.
3. **Фирменный стиль — по мотивам логотипа и фото владельца (светлая деревенская кухня, тёмный деревянный стол, полосатая льняная дорожка, белая посуда)**: фон — стены в утреннем свете `--bg`, лён `--bg-tint`, тёмное дерево `--wood` (край стола на главном экране, подвал, активная вкладка), красный заголовок с фото `--accent` (название, главные кнопки, цены), оранжевый с логотипа `--honey`, серый с логотипа `--gray`. Заголовки — узкий шрифт Oswald, часто ПРОПИСНЫМИ, как на логотипе; текст — системный шрифт. В названии — «ё»: «А ещё есть?». Новые цвета — только через переменные в `:root`.
4. **Звонок, Telegram и WhatsApp открываются одним нажатием**: `tel:+7…`, `https://t.me/…`, `https://wa.me/7…` (номер без «+»). У каждой такой ссылки атрибут `data-goal` (`call`, `telegram`, `whatsapp`) — по нему считаются цели Метрики.
5. **Данные везде одинаковые**: телефон, часы и адрес встречаются в нескольких местах (видимый текст, микроразметка JSON-LD, `js/main.js`). Меняешь в одном — меняй во всех, потом запускай проверку.
6. **Тексты** — по-русски, тёплым простым языком, с «ё», с кавычками-«ёлочками», с длинным тире «—», с неразрывными ценами («1 500 ₽»).
7. **Скорость**: фото блюд — JPG или WebP, около 800×800, до ~200 КБ. Большие фото сжимай перед добавлением (см. ниже).

## Корзина и заказ

Клиент собирает заказ кнопками «+»/«−», закреплённая кнопка показывает «Корзина · N шт. · сумма». В окне заказа — список, итог с доставкой, самовывоз/доставка, адрес, время, имя, комментарий. WhatsApp получает готовый текст через `wa.me/…?text=`; Telegram так не умеет, поэтому текст копируется в буфер с подсказкой. Не ломай этот путь: после любых правок прогоняй `screenshots.js` — он сам проверяет добавление в корзину, текст заказа и сохранение после перезагрузки.

## Частые задачи

### Поменять блюда и цены
Правь только `menu.json`. `price` — число без «₽». Скрыть блюдо — `"available": false`. Новая категория — объект с `id` (латиница, без пробелов, уникальный), `title`, `items`. После правки — проверка.

### Добавить фото блюда
1. Положи файл в `images/`, имя латиницей через дефис: `images/pirog-s-kapustoy.jpg`.
2. Если фото тяжелее ~200 КБ или больше 1200 px — уменьши:
   `python3 -c "from PIL import Image; im=Image.open('IN'); im.thumbnail((1000,1000)); im.convert('RGB').save('OUT.jpg', quality=82, optimize=True)"`
3. Пропиши путь в `photo` у блюда в `menu.json`.

### Поменять контакты, часы, доставку
Сначала `CONFIG` в начале `js/main.js` (телефон, WhatsApp, Telegram, `deliveryPrice`, `freeDeliveryFrom`). Потом найди остальные вхождения через `grep -rn "старое значение" index.html README.md` и замени везде, включая JSON-LD (`telephone`, `openingHoursSpecification`, `sameAs`) и текст про доставку в блоке «Как заказать».

### Яндекс.Метрика
Код счётчика вставляется в `index.html` между `<!-- Яндекс.Метрика: … -->` и `<!-- /Яндекс.Метрика -->`, номер — в `CONFIG.metrikaId` в `js/main.js`. Цели в Метрике — «JavaScript-событие»: `call`, `telegram`, `whatsapp`, `order_open`, `cart_add`.

### Обновить картинку-превью или иконки
Если меняется название, адрес или логотип — перерисуй `images/og-image.jpg` (1200×630) через Playwright (Chromium уже установлен) и иконки из логотипа через Pillow. В маленьких иконках только колпак — надписи логотипа в 32 px не читаются.

## Проверка перед коммитом (обязательно)

```bash
python3 .claude/skills/site-engineer/check.py
node .claude/skills/site-engineer/screenshots.js   # скриншоты в папку preview/ (она в .gitignore)
```

- `check.py` проверяет `menu.json` (структуру, цены, уникальность `id`), что все фото существуют и не слишком тяжёлые, что телефон одинаковый во всех местах, что JSON-LD разбирается и что все файлы сайта перечислены в `pages.yml`.
- `screenshots.js` поднимает локальный сервер, снимает страницу на телефоне (390 px) и компьютере (1280 px), проходит заказ целиком (добавить блюда → корзина → доставка → текст для WhatsApp → сохранение после перезагрузки), сообщает об ошибках JS и горизонтальной прокрутке.

Посмотри скриншоты сам и отправь владельцу самые важные (SendUserFile). Яндекс.Карта в облачной среде может не загрузиться — это нормально, на сайте она работает.

## Публикация

- Сайт собирается из ветки `main` автоматически (`.github/workflows/pages.yml`), обычно 1–2 минуты.
- Работай в своей рабочей ветке, коммить понятными сообщениями на русском, пушь её. В `main` изменения попадают через pull request — создавай его, только если владелец просит опубликовать.
- Один раз в настройках репозитория должно быть включено: Settings → Pages → Source: **GitHub Actions**.
- После публикации проверь, что сайт открывается по адресу выше, и дай владельцу ссылку.
